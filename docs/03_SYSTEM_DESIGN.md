## 2. データフロー
1. 利用者が日付・地域・釣り場・魚種を選ぶ。
2. フロントエンドが環境データを取得する。
3. 取得値を単位・対象時刻・取得元とともに評価処理へ渡す。
4. 評価処理がスコア・構成要素・欠損要素を生成する。
5. 画面に結果と注意事項を表示する。
6. 認証済み利用者の釣行・釣果・観察データをSupabaseへ保存する。
7. 将来、予測時点の環境データと釣行結果を結び、検証・改善に使う。

※ 全段階が実装済みとは限らない。状態は機能仕様書とテスト結果で管理する。

## 3. 評価処理の責務分離（2026-11-26）
- 環境評価は風・波・降水等から魚種共通の環境適合度を返す。
- 魚種評価は魚種プロフィールと季節・水温等から魚種別活動期待度を返す。
- 生態プロフィールの根拠が不足する場合、活動期待度はnull（画面では未評価）とする。
- 表示・AI出力・時間帯グラフ・おすすめプランは指標の意味を維持し、環境適合度を活動期待度として再利用しない。
- 係数・プロフィールは暫定で、実釣データによる校正は未完了。

## 4. セキュリティ
- ブラウザに置けるのは公開用anon/publishable keyのみ。
- service_role/secret key、パスワード、アクセストークンをソース・ログ・分析用コピーへ含めない。
- 個人テーブルはRLSを有効にし、auth.uid()で所有者を制限する。
- 共有データ取込や管理者権限が必要な処理は信頼できるサーバー/Edge Function側で実行する。
- 認証リダイレクトURLは公開ドメインに限定する。

## 5. 障害時
- 外部API失敗時も独立機能を可能な範囲で表示する。
- 部分取得成功と全体成功を区別する。
- 古いデータを最新値のように表示しない。
- 再試行時の重複保存を避ける仕組みを検討する。

## 6. 拡張候補

- 同意制の匿名集計データ共有。
- 自動テストとリリース前チェック。
