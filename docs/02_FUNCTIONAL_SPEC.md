## 2. 釣行結果の状態
- caught: 釣果あり。
- blank: 釣行したが対象となる釣果なし。
- no_fishing: 釣行していない、または中止。ボウズ集計しない。
- unknown: 結果未確定・未入力。

## 3. 検索・絞り込み
- 魚種指定検索では指定魚種だけを候補にする。
- 全魚種指定では対象範囲内の登録魚種を候補にする。
- 釣り場指定時の魚種条件の優先順位は画面仕様として統一する。
- 条件に一致する候補がない場合、別魚種を混ぜず「該当なし」と表示する。
- 適用中の絞り込み条件を画面上に明示する。

## 4. データ表示
- 値には単位を表示する。
- 予報・モデル推定・実測・ユーザー観察を区別する。
- 取得できない値は「未取得」等とし、0と表示しない。
- 対象時刻と取得時刻を可能な範囲で表示する。
- スコアには名称、算出対象、評価時刻、根拠、欠損要素を併記する。

## 5. スコア表示・検索の追加仕様
- おすすめ釣行プランの対象魚種選択は検索モードにかかわらず適用する。
- 環境適合度は風・波・降水等から魚種共通で評価する。
- 魚種別活動期待度は魚種固有の季節・水温要因を評価する。必要情報が揃わない場合は未評価とする。
- 24時間グラフは環境適合度の時間推移として表示する。
- おすすめプランは活動期待度を算出できる魚種のみ順位付けし、環境適合度と釣り場タイプ適合は別表示する。
- データ充実度は評価済み項目数/対象項目数で表示する。

## 6. 自動環境データ収集の仕様
- 初期の定期取得間隔は60分とする。
- 30分取得は、データ提供元が十分な更新頻度で有用なデータを提供する項目に限定する。
- 取得処理の実行間隔と、提供元の観測/予報データ更新間隔を区別する。
- 取得対象はdata_collection_targetsで地点単位またはエリア単位に管理する。
- environment_snapshotsに対象時刻、取得時刻、提供元、データ種別、値、単位、品質情報を保存する。
- 予報履歴は上書きせず、取得時点ごとに保持する。
- 定期処理の実行結果はdata_collection_runsへ記録する。
- 欠損はNULL/欠損理由で表し、0で補完しない。
- 定期処理はEdge Function等のサーバー側で行い、service_roleキーをブラウザへ配置しない。
- SQL追加だけでは自動取得は開始されない。DBへのDDL適用、対象地点登録、外部API接続、Cron設定が必要。

## 7. エラー・例外
- 通信失敗: 再試行可能なメッセージを表示。
- API応答に対象項目がない: 欠損として扱う。
- 認証切れ: 個人データ操作前に再ログインを案内。
- DB書込失敗: 保存成功と誤認させず、エラー表示。
- 検索結果0件: 空状態を表示し、別魚種で埋めない。

## 8. DB接続状態表示
- 起動時にSupabase REST APIの読み取り確認を行い、fishing_spotsテーブルへのアクセス可否を表示する。
- 接続確認中のまま無期限に待機させず、10秒でタイムアウト表示へ遷移する。
- DB接続確認は後続の画面初期化処理より前に開始する。
- 「DB接続OK」はfishing_spotsの公開読み取り確認のみを意味し、認証・書き込み成功を保証しない。
